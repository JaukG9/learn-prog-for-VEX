Basic C++

Goal: Read and write the small amount of C++ used in VEX code.

Variables & Types

int motorPort = 6;          // whole number
double inches = 3.25;       // decimal number
bool clawClosed = true;     // true or false

The first part (red) is the type that defines how the variable will behave. The second part is the name of the variable. The part after the = is what you're setting it to

Functions

// takes in an int n, and gives back twice n
int doubleIt(int n){
    return n * 2;
}

Having a type (like int) before a function says that the function will return a value of that type. In this case, we see that it takes a parameter int n, doubles it and returns the integer equal to 2 * n.

Conditionals and Loops

if(speed > 100){
    speed = 100;            // limit the speed to 100
}else{
    speed = speed + 1;      // increase speed by 1
}

while(true){                // repeat forever
    // do robot stuff
}

The if statement checks if the speed is greater than 100. If it is, it sets it back to 100 (essentially limits it). Otherwise, it adds 1 to it. The while loop infinitely runs, doing whatever is inside of it.

Objects

pros::Motor motor(1);       // create a motor object for port 1
motor.move_velocity(200);   // move the motor at 200rpm

An object is very similar to a variable. Instead, you define it by calling the type (like pros::Motor), then the name (like motor), then any parameters (the port 1 in this case).

The pros:: and lemlib:: that you see before things are called namespaces. They tell C++ where something comes from, pulling code from other files we imported.

Reading the Controller

pros::Controller controller(pros::E_CONTROLLER_MASTER)  // creates a controller object called "controller"

void opcontrol(){
    pros::Motor lift(2);
    
    if(controller.get_digital(pros::E_CONTROLLER_DIGITAL_R1)){          // are you pressing R1?
        lift.move_velocity(200);
    }else if(controller.get_digital(pros::E_CONTROLLER_DIGITAL_R2)){    // are you pressing R2?
        lift.move_velocity(-200);
    }else{
        lift.brake();
    }

    pros::delay(20);
}

Quick note: When reading the controller, using controller.get_digital gives a button press (0 or 1), while using controller.get_analog gives a joystick input (range from -127 to 127).

Printing for Debugging

Sometimes you need to look at some value to debug your code. To do this, we can print to the brain or terminal.

pros::lcd::print(0, "Angle: %f", chassis.getPose().theta)   // prints a float to the brain which is the angle
printf("Hello from the terminal.")                          // prints to the PROS terminal instead of the brain

Driver Control

Goal: Drive with a controller using tank or arcade, and a deadband.

Tank vs. Arcade

  • Tank Drive
    • The left joystick controls the left side of the drivertrain
    • The right joystick controls the right side of the drivetrain
  • Arcade Drive
    • The left joystick controls the forward and back motion
    • The right joystick controls the turning motion
pros::MotorGroup left_mg({-1, -2});     // negative = reversed
pros::MotorGroup right_mg({3, 4});

void opcontrol(){
    while(true){
        int forward = controller.get_analog(pros::E_CONTROLLER_ANALOG_LEFT_Y);      // vertical component of left joystick
        int turning = controller.get_analog(pros::E_CONTROLLER_ANALOG_RIGHT_X);     // horizontal component of right joystick

        // deadband to ignore stick drift
        if(abs(forward) < 5) forward = 0;
        if(abs(turning) < 5) turning = 0;

        left_mg.move(forward + turn);
        right_mg.move(forward - turn);

        pros::delay(20);
    }
}

We will look at an easier way to do this later, but for now this is the simplest implementation. Can you tell whether this is tank or arcade drive?

Try swapping it to tank drive. How would you do this?

Toggle vs. Hold

There are two ways to actuate pistons or motors. Either you can toggle them or hold them.

  • Toggle: If you press the button it switches the state. When you press it again, it switches back.
  • Hold: The state is switched based on whether or not you're holding the button.
bool clawClosed = false;

while(true){
    if(controller.get_digital_new_press(pros::E_CONTROLLER_DIGITAL_A)){
        clawClosed = !clawClosed;       // set to false if it's true, and set to true if it's false
        claw.set_value(clawClosed);
    }

    pros::delay(20);
}

The .get_digital_new_press checks if a button was pressed after not being pressed. This is useful for toggles.

VEX Programming Concepts

Goal: Understand essential programming concepts surrounding odometry.

Time-based Autons

Unfortunately, when programming for VEX, we cannot use simple time-based autonomous routines. Saying "drive forward for 1 second" has too much ambiguity. There can be inconsistencies in the floor tiles, battery, drivetrain motors, etc.

To address this, we use feedback loops, also known as PID.

PID in Plain English

There are three parts to PID: proportional (P), integral (I), and derivative (D). Using these, the robot is able to reach its target effectively.

  • Proportional
    • Used to address "current" error
    • Looks at the current error and moves to close the gap
  • Integral
    • Used to address "past" error
    • Looks at consistent past errors and accounts for it
  • Derivative
    • Used to address "future" error
    • Looks at the slope of change to address any future errors

Odometry

Odometry is how the robot tracks its position (x, y) and heading θ. It uses sensor data (IMU, tracking wheels, motor encoders). LemLib does this for you in the background, so you can just say something like "go to (24, 48)" and the robot will know.

LemLib Fundamentals

Goal: Describe your robot to LemLib so it can move accurately.

Using LemLib

First, you must install LemLib. Follow the instructions on its official setup page.

In main.cpp, you can then do something likethis:

#include "lemlib/api.hpp"       // put this at the top of your file
 
pros::MotorGroup left_mg({-1, -2, -3}, pros::MotorGearset::blue);
pros::MotorGroup right_mg({4, 5, 6}, pros::MotorGearset::blue);
pros::Imu imu(10);

// define the drivetrain
lemlib::Drivetrain drivetrain(&left_mg,                     // left motor group
                              &right_mg,                    // right motor group
                              11.5,                         // track width (in.)
                              lemlib::Omniwheel::NEW_325,   // wheel type
                              450,                          // rpm
                              2                             // horizontal drift
);                           

//lateral PID controller
lemlib::ControllerSettings lateral_controller(6.5,  // proportional gain (kP)
                                              0,    // integral gain (kI)
                                              10,   // derivative gain (kD)
                                              0,    // anti windup
                                              1,    // small error range, in inches
                                              100,  // small error range timeout, in milliseconds
                                              3,    // large error range, in inches
                                              500,  // large error range timeout, in milliseconds
                                              20    // maximum acceleration (slew)
);

// angular PID controller
lemlib::ControllerSettings angular_controller(2.5,  // proportional gain (kP)
                                              0,    // integral gain (kI)
                                              15,   // derivative gain (kD)
                                              0,    // anti windup
                                              1,    // small error range, in degrees
                                              100,  // small error range timeout, in milliseconds
                                              3,    // large error range, in degrees
                                              500,  // large error range timeout, in milliseconds
                                              0     // maximum acceleration (slew)
);

// odometry settings
lemlib::OdomSensors sensors(
    nullptr,                    // vertical tracking wheel 1
    nullptr,                    // vertical tracking wheel 2
    &horizontal_tracking_wheel, // horizontal tracking wheel 1
    nullptr,                    // horizontal tracking wheel 2
    &imu                        // inertial sensor
);

// create the chassis
lemlib::Chassis chassis(drivetrain,         // drivetrain settings
                        lateral_controller, // lateral PID settings
                        angular_controller, // angular PID settings
                        sensors             // odometry sensors
);

void initialize() {
    pros::lcd::initialize();
    chassis.calibrate();     // REQUIRED: calibrates the IMU, starts odometry
}

Note: The umbers above are placeholders. You must always measure your track width (distance between left and right wheel centers), wheel diameter, and drivetrain RPM (motor RPM * gear ratio). Wrong values are the #1 cause of inaccurate autonomous.

Driver Control with LemLib

We learned how to implement drive styles earlier, but LemLib makes it a lot easier. Below is an arcade drive example:

void opcontrol() {
    while(true){
        int leftY  = master.get_analog(pros::E_CONTROLLER_ANALOG_LEFT_Y);
        int rightX = master.get_analog(pros::E_CONTROLLER_ANALOG_RIGHT_X);
        chassis.arcade(leftY, rightX);
        pros::delay(20);
    }
}

LemLib Motions

LemLib's coordinate system is very simple:

  • Units are in inches and degrees
  • +Y is forward and +X is to the right
  • Heading 0° points along +Y and increases clockwise (90° = facing right)
void autonomous(){
    chassis.setPose(0, 0, 0);               // tell LemLib where to start
    chassis.moveToPoint(0, 24, 4000);       // drive to (0, 24) with a 4 second timeout
    chassis.turnToHeading(90, 2000);        // turn to 90° (facing right)
    chassis.moveToPose(24, 48, 90, 4000);   // go to (24, 48) ending at a 90° angle
    chassis.moveToPoint(0, 0, 4000, {.forwards = false});   // back up to the start
}
Function Does
setPose(x, y, θ) Gives the robot a current position
turnToHeading(θ, timeout) Turn in place to a specific heading (angle)
moveToPoint(x, y, timeout) Turn toward then drive to a point
moveToPose(x, y, θ, timeout) Drive a curved path to a specific point and angle

You can add extra parameters like {.maxSpeed = } to limit the speed, or {.forwards = false} to move backwards.

Field Simulator

Type commands (one per line) and press Run. The field is 144" x 144" with the origin at the center. +Y is up, +X is right, and heading 0° faces up (90° faces right).

Pose: x=0.0 y=0.0 θ=0.0°

Commands: setPose(x, y, θ), turnToHeading(θ), moveToPoint(x, y), moveToPose(x, y, θ). This is simplified, so don't use it to tune PID.

Challenge: Start at (-48, -48) facing 0°. Make the robot visit (-48, 0), then (0, 0), then end at (48, 48) facing 180°.

Tuning & Debugging Tips

Some rules to go by when tuning PID:

  • Oscilates around the target: decrease kP or increase kD
  • It's slow when settling: increase kP a bit
  • Always print the position to the screen to check
